Universal · Client-side · Android

Force the Meta / Oculus entitlement check to pass — on any APK.

A tiny native library that patches the Oculus Platform SDK result in-memory, so ovr_Message_IsError always returns a clean entitlement. No OBB touched. No il2cpp rewrites. Drop in, early-load, launch.

What it does

The Meta Platform SDK hands your app a Message handle, and your code calls ovr_Message_IsError plus ovr_Message_GetType to find out whether the user owns the app. entpass hooks the result path and forces a clean reply — nothing else moves.

⌁

Pure client-side

Only the in-process check is forced. Server-side entitlement, bans, and anti-cheat remain untouched.

◎

Game-agnostic

Works on Gorilla Tag, other VR titles, sideloaded SPM builds, and non-VR Meta-integrated games.

⟲

Patient resolver

Retries for ~6s if the platform loader is not present at constructor time (common on Unity titles).

↯

No OBB churn

Only the base APK is replaced. OBB, il2cpp, and asset packs stay exactly where they are.

⬢

Both ABIs

Ships arm64-v8a and armeabi-v7a. Most Quest titles are arm64 only.

∞

Universal source

No per-game constants. One libentpass.cpp handles the whole SDK surface.

Quickstart

Five commands between you and a patched APK. Keep this handy; the full guide below covers every step with context.

# 1. build both ABIs
chmod +x scripts/build_so.sh
./scripts/build_so.sh

# 2. unpack the target
apktool d GAME.apk -o game_src

# 3. drop the lib
mkdir -p game_src/lib/arm64-v8a
cp out/arm64-v8a/libentpass.so game_src/lib/arm64-v8a/

# 4. edit the launcher activity's onCreate — insert the smali snippet
#    (see "Force early load" below)

# 5. rebuild · align · sign · install
apktool b game_src -o game_entpass.apk
zipalign -f 4 game_entpass.apk game_entpass_aligned.apk
apksigner sign --ks your.keystore --ks-key-alias youralias \
  --out GAME-entpass.apk game_entpass_aligned.apk
adb install -r GAME-entpass.apk
Prereqs: Android NDK r23+, apktool, zipalign, apksigner, and a keystore (the debug keystore is fine for personal use).

Full guide

Every step. Nothing waved at. If any of this reads differently than your APK on disk, trust the APK — it's your source of truth for ABIs and the launcher activity.

  1. Build the library

    Point ANDROID_NDK_HOME at your NDK and run the script. Both ABIs land under out/.

    export ANDROID_NDK_HOME=/path/to/ndk
chmod +x scripts/build_so.sh
./scripts/build_so.sh

# produces:
# out/arm64-v8a/libentpass.so
# out/armeabi-v7a/libentpass.so

  2. Unpack the APK

    Decode with apktool. The resulting tree is where everything else happens.

    apktool d GAME.apk -o game_src

  3. Drop in the native library

    Match the ABI folders the original APK already ships. If lib/armeabi-v7a isn't in the original, don't invent it.

    mkdir -p game_src/lib/arm64-v8a
cp out/arm64-v8a/libentpass.so game_src/lib/arm64-v8a/

# only if the original APK also contains armeabi-v7a:
mkdir -p game_src/lib/armeabi-v7a
cp out/armeabi-v7a/libentpass.so game_src/lib/armeabi-v7a/

  4. Force early load (smali)

    Find the launcher activity in AndroidManifest.xml — the one with both MAIN and LAUNCHER intent filters. Open its .smali file under smali*/…. Common targets:

    • com/unity3d/player/UnityPlayerActivity.smali
    • com/unity3d/player/UnityPlayerGameActivity.smali
    • the package-specific launcher activity

    Locate .method protected onCreate(Landroid/os/Bundle;)V. Immediately after the .locals N / .registers N line, insert:

        const-string v0, "entpass"
    invoke-static {v0}, Ljava/lang/System;->loadLibrary(Ljava/lang/String;)V

    If register v0 is already live, use any free register. Alternative early-load points that also work: Application.onCreate, the main activity's static constructor, or any class guaranteed to load before the Platform SDK.

  5. Rebuild

    apktool b game_src -o game_entpass.apk

  6. Align & sign

    zipalign first, then apksigner. A debug keystore is fine if you don't have a release one.

    zipalign -f 4 game_entpass.apk game_entpass_aligned.apk

apksigner sign --ks your.keystore --ks-key-alias youralias \
  --out GAME-entpass.apk game_entpass_aligned.apk

  7. Install

    Only the base APK is replaced. Existing OBB and data folders stay where they are.

    adb install -r GAME-entpass.apk

Verify

Tail logcat with the right tags and watch for the resolve line. If you see it, the entitlement path is clean.

adb logcat -s entpass Unity MetaAuthenticator Oculus Platform
Expected:
I/entpass: libentpass constructor (universal)
I/entpass: JNI_OnLoad
I/entpass: symbols resolved – entitlement path forced clean

Or, if the platform library loads later:
I/entpass: found already-loaded libovrplatformloader.so
I/entpass: symbols resolved – entitlement path forced clean

The original “user does not have app in library” line should no longer appear.

Troubleshooting

If something looks off, start here. If the symbol resolve line never arrives, the problem is almost always ABI mismatch or wrong load point.

SymptomAction
platform loader not present yet forever Confirm the APK actually links a libovrplatform*.so; inspect the lib/ folders after unpack.
Symbols resolved but check still fails Update OVR_MESSAGE_ENTITLEMENT from a dump of the platform library and rebuild.
loadLibrary fails at runtime ABI mismatch — copy the correct out/<abi>/ folder into the APK's matching lib/<abi>/.
apktool rebuild errors Use the same apktool version that decoded cleanly; fix framework jars if needed.

Notes

  • OBB / il2cpp / asset packs stay exactly where they are. Only the base APK is touched.
  • The library retries for ~6 s if the platform loader is not present at constructor time (common on some Unity titles).
  • If a title still fails after symbols resolve, the message-type constant may differ. Dump the platform .so, update OVR_MESSAGE_ENTITLEMENT in src/libentpass.cpp, and rebuild.
  • For instruction-level trampolines (rare), swap in Dobby or And64InlineHook. The current implementation is enough for the vast majority of sideloaded builds because the managed callback only inspects the IsError return value.
  • Client-side only. Server entitlement, bans, and anti-cheat are unaffected.
